# UI/UX Portfolio Expert Review — Interaction, Visual Quality, Responsive Design, and Conversion

You are reviewing Sebastian Marin's portfolio as a senior UI/UX designer specialized in developer portfolios and premium SaaS-style interfaces.

Your job is to be brutally honest about whether the site looks like a high-quality portfolio or an AI-generated generic programmer website.

Focus on actual user experience.

## Inputs

Use the following in this order:

1. Live portfolio URL.
2. Full browser interaction at multiple breakpoints.
3. Screenshots if generated.
4. Source code only after experiencing the site.
5. CV/resume only for content alignment after the UI/UX review.

## Browser-First Rule

Do not start by reading code.

Use the live site as a real user.

You may inspect code later to diagnose problems, but your main review must be based on the rendered experience.

## Required Viewports

Test or simulate:

- 360px mobile
- 390px mobile
- 768px tablet
- 1024px laptop
- 1440px desktop
- 1920px large display

For each, inspect:

- hero;
- navigation;
- project cards;
- case study section;
- contact CTA;
- footer;
- scroll behavior;
- animation quality;
- horizontal overflow;
- tap target size;
- visual hierarchy.

## Interaction Review

Test:

- navbar links;
- project cards;
- external links;
- CV download;
- GitHub links;
- contact buttons;
- hover states;
- focus states;
- scroll-triggered animations;
- reduced-motion behavior if implemented.

If any side project does not work, flag it clearly.

## Design Evaluation

Evaluate:

- layout originality;
- premium/enterprise feel;
- typography;
- spacing;
- visual rhythm;
- color system;
- card design;
- screenshot presentation;
- animation restraint;
- mobile polish;
- conversion clarity.

## Portfolio-Specific Evaluation

A strong developer portfolio should answer:

1. Who is this person?
2. What kind of work do they do?
3. What proof exists?
4. Which project should I click first?
5. Can I contact or interview them easily?

If the site does not answer these quickly, explain why.

## Harsh Review Areas

Be especially critical of:

- generic AI layout;
- fake technical sophistication;
- decorative maps that do not do anything;
- broken project demos;
- unclear CTA;
- excessive buzzwords;
- too many badges;
- cards with no proof;
- animations that feel template-like;
- poor mobile hierarchy;
- sections that exist only because portfolios usually have them.

## Improvement Recommendations

Give:

### Must Fix Before Sending

Only blockers.

### High-Impact Improvements

Things that would make the site feel 2x better.

### Remove or Hide

Things that damage credibility.

### Make It Feel Less Like It Is Trying to Fit Geolabs

Specific suggestions:

- wording changes;
- visual changes;
- project ordering changes;
- remove over-obvious geospatial language where needed;
- show broader engineering capability.

### Better Interaction Ideas

Suggest realistic interactions:

- project hover preview;
- map/data mini preview;
- sticky project navigation;
- case-study tabs;
- before/after technical diagrams;
- scroll progress;
- motion improvements.
